# Приёмник событий с очередью обработки

Небольшой сервис на Flask и SQLite. `POST /webhook` сохраняет событие и задачу в одной транзакции, отдельный воркер обрабатывает очередь, а `GET /stats` возвращает агрегированные счётчики.

## Запуск

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

Во втором терминале, с активированным окружением:

```bash
python worker.py
```

По умолчанию сервер доступен по адресу `http://127.0.0.1:5000`, база создаётся в `instance/events.sqlite3`.

Пример запроса:

```bash
curl -X POST http://127.0.0.1:5000/webhook \
  -H 'Content-Type: application/json' \
  -d '{"event_id":"abc-123","type":"payment_succeeded","payload":{"amount":500}}'
```

Поддержаны обработчики `payment_succeeded` и `user_registered`. Для проверки повторных попыток можно передать в `payload` поле `"simulate_failure": true`. Неизвестные типы событий получают статус `skipped`.

## Тесты

```bash
pytest
```

## Принятые решения

- Событие и задача создаются в одной транзакции. Уникальный индекс на `event_id` защищает от дублей, в том числе при одновременных запросах.
- Задача захватывается внутри `BEGIN IMMEDIATE`, поэтому несколько воркеров не возьмут её одновременно.
- Номер попытки увеличивается при захвате задачи. Если воркер аварийно завершится, блокировка протухнет, задача снова станет доступна. После трёх прерванных или неуспешных попыток она перейдёт в `failed`.
- Пауза перед повтором растёт по схеме 2, 4 секунды. Значения задержек, таймаута блокировки и интервала опроса задаются в конфигурации приложения.
- SQLite работает в WAL-режиме, чтобы чтение статистики не мешало записи событий и работе воркера.

Для учебного сервиса воркер запускается отдельным процессом вручную. В рабочем окружении его следовало бы запускать под менеджером процессов, который перезапускает его после сбоя.
